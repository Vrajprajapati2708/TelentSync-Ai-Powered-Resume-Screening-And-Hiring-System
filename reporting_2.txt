6.1 ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
HireAI (TalentSync) is architected as a modular, high-performance 3-Tier Web 
Application integrating classical machine learning (TF-IDF vectorization, Cosine 
Similarity) and Deep NLP (spaCy Named Entity Recognition, Tesseract OCR) with an 
asynchronous RESTful application layer.

The architecture comprises three primary tiers:

1. Presentation Tier (Frontend Client):
   - Built as a responsive Single-Page Application (SPA) using HTML5, CSS3, 
     Vanilla JavaScript (ES6+), and SVG vector data visualizations.
   - Communicates asynchronously with the backend using Fetch API over secure 
     JSON REST endpoints.
   - Provides role-segregated user interfaces for Candidates and HR Recruiters.

2. Application & Intelligence Tier (Flask Backend & ML Engines):
   - Controller & Routing Layer: Flask WSGI application managing route dispatch, 
     session authentication, RBAC authorization, and input sanitization.
   - Resume Ingestion & Parsing Engine: High-throughput PyPDF2, python-docx, and 
     Tesseract OCR fallback parsing pipeline with magic-byte file signature validation.
   - NLP & Extraction Pipeline: spaCy NER and regex tokenizers extracting 
     contact metadata, canonical skills (80+ technical clusters), experience, and education.
   - Recommendation & Ranking Engine: Scikit-learn TF-IDF vectorizer + Cosine 
     Similarity engine computing multi-factor weighted match scores (Role 40%, 
     Skills 40%, Experience 15%, Location 5%).
   - Live Job Fetching Engine: Resilient client integrating external job providers 
     (Adzuna REST API) with local SQLite fallback and SSRF-protected redirects.

3. Persistence Tier (Relational Storage & Filesystem):
   - Primary Database: SQLite3 (talentsync.db) operating in WAL (Write-Ahead Logging) 
     mode with foreign key enforcement and indexed lookups.
   - Resume Storage: SHA-256 content-addressed filesystem storage protecting against 
     directory traversal and file overwrite attacks.


6.2 DESIGN PRINCIPLES & CONSTRAINTS
--------------------------------------------------------------------------------
1. Separation of Concerns (SoC): Strict boundary isolation between REST controllers, 
   domain repositories, ML inference pipelines, and presentation views.
2. Security by Design: Argon2/Bcrypt salted password hashing, HTTP-only SameSite 
   cookies, cryptographic password reset tokens, and parameterized SQL queries.
3. Fail-Safe AI Fallbacks: If external APIs (Adzuna) experience rate limiting or 
   network latency, the recommendation pipeline seamlessly falls back to local 
   curated database jobs without user disruption.
4. Explainable Scoring: Every ATS match score is decomposed into explainable 
   sub-factors (contact, education, experience, skill match, format health).

7.3 ACTIVITY DIAGRAM
--------------------------------------------------------------------------------
The Activity Diagram documents the execution flow for the system's core pipeline:
"Resume Ingestion, Multimodal Parsing, NLP Skill Extraction, and AI Job Recommendation."

7.3.1 Workflow Steps:
1. Start: Candidate submits a resume file via Drag-and-Drop on the UI.
2. File Validation: Verify file type (PDF/DOCX) and size (<10MB).
   - If invalid: Return HTTP 400 with user-friendly error message -> Terminate.
3. Secure File Write: Compute SHA-256 hash, save to isolated storage.
4. Text Extraction Decision:
   - If PDF: Run PyPDF2 text extraction.
   - Quality Check: Did PyPDF2 extract sufficient text?
     - YES -> Proceed to Text Cleaning.
     - NO (Scanned/Image PDF) -> Trigger Tesseract OCR fallback engine.
   - If DOCX: Run python-docx XML paragraph and table parser.
5. NLP Skill Intelligence: Run spaCy NER model + Regex entity matcher 
   against canonical skill database (80+ clusters).
6. ATS Scoring: Calculate multi-factor score:
   Score = (Skills * 0.40) + (Experience * 0.25) + (Education * 0.15) + (Format * 0.20).
7. Job Recommendation Request:
   - Query Adzuna HTTPS Live API with extracted candidate skills.
   - Was Adzuna query successful (HTTP 200 with > 0 jobs)?
     - YES -> Normalize external job payload (title, salary, company, apply_url).
     - NO (Timeout/Offline/Empty) -> Retrieve curated fallback jobs from local SQLite DB.
8. AI Ranking Algorithm:
   - Compute TF-IDF matrix between candidate skill profile and job requirements.
   - Compute Cosine Similarity between vectors.
   - Compute Deterministic Experience Score [0.0 - 1.0].
   - Compute Final Match Percentage = (Role*0.40 + Skill*0.40 + Exp*0.15 + Loc*0.05).
9. Output Presentation: Sort jobs descending by match percentage and render 
   interactive job cards on Candidate Dashboard with Direct External Apply links.
10. End.

9.1 RELATIONAL SCHEMA (SQL DDL SPECIFICATION)
--------------------------------------------------------------------------------
Below is the clean, verified Data Definition Language (DDL) representing the 
finalized relational database schema in SQLite:

```sql
-- 1. USERS TABLE
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    password TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'candidate' CHECK(role IN ('candidate', 'hr', 'admin')),
    is_verified INTEGER NOT NULL DEFAULT 0 CHECK(is_verified IN (0, 1)),
    skills TEXT DEFAULT '',
    ats_score INTEGER DEFAULT 0 CHECK(ats_score BETWEEN 0 AND 100),
    phone TEXT DEFAULT '',
    location TEXT DEFAULT '',
    linkedin TEXT DEFAULT '',
    github TEXT DEFAULT '',
    summary TEXT DEFAULT '',
    education TEXT DEFAULT '',
    is_outlier INTEGER DEFAULT 0,
    cluster_label TEXT DEFAULT 'Unclustered',
    created_at TEXT DEFAULT (datetime('now'))
);

-- 2. RESUMES TABLE
CREATE TABLE IF NOT EXISTS resumes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    original_name TEXT NOT NULL,
    stored_filename TEXT NOT NULL UNIQUE,
    file_path TEXT NOT NULL,
    file_hash TEXT NOT NULL,
    file_size_bytes INTEGER NOT NULL,
    mime_type TEXT NOT NULL,
    parsed_text TEXT DEFAULT '',
    word_count INTEGER DEFAULT 0,
    ats_score INTEGER DEFAULT 0 CHECK(ats_score BETWEEN 0 AND 100),
    extracted_skills TEXT DEFAULT '',
    structured_json TEXT DEFAULT '',
    status TEXT DEFAULT 'processed',
    version INTEGER DEFAULT 1,
    uploaded_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 3. INTERNAL JOBS TABLE
CREATE TABLE IF NOT EXISTS jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    company TEXT NOT NULL,
    location TEXT DEFAULT '',
    type TEXT DEFAULT 'Full-time',
    salary TEXT DEFAULT '',
    skills TEXT DEFAULT '',
    description TEXT DEFAULT '',
    status TEXT DEFAULT 'Active' CHECK(status IN ('Active', 'Closed', 'Draft')),
    created_at TEXT DEFAULT (datetime('now'))
);

-- 4. EXTERNAL JOBS TABLE (Adzuna Feed)
CREATE TABLE IF NOT EXISTS external_jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    external_id TEXT NOT NULL UNIQUE,
    provider TEXT NOT NULL,
    title TEXT NOT NULL,
    company TEXT NOT NULL,
    company_id TEXT DEFAULT '',
    company_logo TEXT DEFAULT '',
    industry TEXT DEFAULT '',
    location TEXT DEFAULT '',
    country TEXT DEFAULT '',
    latitude REAL DEFAULT 0.0,
    longitude REAL DEFAULT 0.0,
    salary_min REAL DEFAULT 0.0,
    salary_max REAL DEFAULT 0.0,
    currency TEXT DEFAULT '',
    employment_type TEXT DEFAULT '',
    experience TEXT DEFAULT '',
    remote INTEGER DEFAULT 0,
    description TEXT DEFAULT '',
    skills TEXT DEFAULT '',
    benefits TEXT DEFAULT '',
    education TEXT DEFAULT '',
    posted_date TEXT DEFAULT '',
    expires_date TEXT DEFAULT '',
    apply_url TEXT DEFAULT '',
    source_url TEXT DEFAULT '',
    language TEXT DEFAULT 'en',
    status TEXT DEFAULT 'Active',
    created_at TEXT DEFAULT (datetime('now'))
);

-- 5. RECOMMENDATION HISTORY TABLE
CREATE TABLE IF NOT EXISTS recommendation_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    match_score INTEGER DEFAULT 0 CHECK(match_score BETWEEN 0 AND 100),
    matched_skills TEXT DEFAULT '',
    missing_skills TEXT DEFAULT '',
    recommended_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 6. SAVED JOBS TABLE
CREATE TABLE IF NOT EXISTS saved_jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    job_id INTEGER DEFAULT NULL,
    external_id TEXT DEFAULT NULL,
    saved_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 7. EMAIL VERIFICATION TOKENS TABLE
CREATE TABLE IF NOT EXISTS email_verification_tokens (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    token_hash TEXT NOT NULL UNIQUE,
    expires_at TEXT NOT NULL,
    is_used INTEGER DEFAULT 0 CHECK(is_used IN (0, 1)),
    created_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 8. PASSWORD RESET TOKENS TABLE
CREATE TABLE IF NOT EXISTS password_reset_tokens (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    token_hash TEXT NOT NULL UNIQUE,
    expires_at TEXT NOT NULL,
    is_used INTEGER DEFAULT 0 CHECK(is_used IN (0, 1)),
    created_at TEXT DEFAULT (datetime('now')),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 9. PROVIDER CACHE TABLE
CREATE TABLE IF NOT EXISTS provider_cache (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    query_hash TEXT NOT NULL UNIQUE,
```

9.2 INDEXES & PERFORMANCE OPTIMIZATIONS
--------------------------------------------------------------------------------
To achieve sub-25 millisecond query execution under concurrent candidate load, 
the schema specifies the following compound and specialized indexes:

```sql
-- User and Authentication Lookups
CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
CREATE INDEX IF NOT EXISTS idx_users_role ON users(role);

-- Resume Duplication and Candidate Retrieval
CREATE INDEX IF NOT EXISTS idx_resumes_user ON resumes(user_id);
CREATE INDEX IF NOT EXISTS idx_resumes_hash ON resumes(file_hash);

-- Token Lookups for Fast Validation
CREATE INDEX IF NOT EXISTS idx_email_tokens_hash ON email_verification_tokens(token_hash);
CREATE INDEX IF NOT EXISTS idx_email_tokens_user ON email_verification_tokens(user_id);
CREATE INDEX IF NOT EXISTS idx_reset_tokens_hash ON password_reset_tokens(token_hash);
CREATE INDEX IF NOT EXISTS idx_reset_tokens_user ON password_reset_tokens(user_id);

-- Recommendation History and Notifications
CREATE INDEX IF NOT EXISTS idx_recs_user ON recommendation_history(user_id);
CREATE INDEX IF NOT EXISTS idx_notifs_user_unread ON notifications(user_id, is_read);

-- External Cache Acceleration
CREATE INDEX IF NOT EXISTS idx_cache_hash_exp ON provider_cache(query_hash, expires_at);
```

9.3 REFERENTIAL INTEGRITY & ER RELATIONSHIPS
--------------------------------------------------------------------------------
1. USERS (1) <----> (M) RESUMES:
   - One user can upload multiple versioned resumes over time.
   - Foreign key `resumes.user_id` strictly references `users.id`.
   - `ON DELETE CASCADE`: Deleting an account removes associated uploaded resumes.

2. USERS (1) <----> (M) RECOMMENDATION_HISTORY:
   - Captures historical match outputs across candidate search sessions.
   - Foreign key `recommendation_history.user_id` references `users.id`.

3. USERS (1) <----> (M) EMAIL_VERIFICATION_TOKENS & PASSWORD_RESET_TOKENS:
   - Tracks security tokens issued for account verification and password reset.
   - Strict 1:M relationship with automatic cascade cleanup upon account removal.

4. USERS (1) <----> (M) SAVED_JOBS:
   - Associates bookmarked opportunities (both local and external) to a candidate.
