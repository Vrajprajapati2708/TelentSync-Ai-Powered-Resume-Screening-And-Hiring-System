1. OVERVIEW OF CORE SYSTEM ARCHITECTURE & MAIN TABLES
================================================================================

HireAI / TalentSync operates on a candidate-job matching and applicant tracking
system (ATS) architecture. The application is driven by 11 core database tables:

1. users                      -> User (Candidate, HR/Recruiter, Admin)
2. jobs                       -> Job (Internal job vacancies)
3. external_jobs              -> ExternalJob (Live vacancies fetched via Adzuna API)
4. resumes                    -> Resume (Uploaded PDF/DOCX metadata & parsed JSON)
5. applications               -> Application (Central Candidate-to-Job application link)
6. application_status         -> ApplicationStatusHistory (Audit log of application status changes)
7. saved_jobs                 -> SavedJob (Candidate bookmarked vacancies)
8. recommendation_history     -> RecommendationHistory (AI match calculations log)
9. notifications              -> Notification (In-app alerts for status & profile views)
10. email_verification_tokens -> EmailVerificationToken (One-time SHA-256 account verification)
11. password_reset_tokens     -> PasswordResetToken (One-time SHA-256 password recovery)

Domain Enumerations:
- UserRole:          'candidate', 'hr', 'admin'
- ApplicationStatus: 'Reviewing', 'Shortlisted', 'Pending', 'Rejected'
- JobStatus:          'Active', 'Closed', 'Draft'
- ResumeStatus:       'uploaded', 'processing', 'processed', 'failed'
- NotificationType:   'info', 'success', 'error', 'warning', 'profile_view'

2. SQL SCHEMA OF MAIN DATABASE TABLES (DDL & CONSTRAINTS)
================================================================================

-- 1. USERS TABLE (Identity, Authentication & Candidate Profile)
CREATE TABLE users (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    name           TEXT    NOT NULL,
    email          TEXT    UNIQUE NOT NULL,
    password       TEXT    NOT NULL,
    role           TEXT    NOT NULL DEFAULT 'candidate', -- 'candidate' | 'hr' | 'admin'
    is_verified    INTEGER DEFAULT 0,                    -- 0 = unverified/inactive, 1 = verified/active
    skills         TEXT    DEFAULT '',                   -- Comma-separated extracted skills
    ats_score      INTEGER DEFAULT 0,                    -- Overall ATS compatibility score (0-100)
    phone          TEXT    DEFAULT '',
    location       TEXT    DEFAULT '',
    linkedin       TEXT    DEFAULT '',
    github         TEXT    DEFAULT '',
    summary        TEXT    DEFAULT '',
    education      TEXT    DEFAULT '',
    is_outlier     INTEGER DEFAULT 0,                    -- 0 = normal, 1 = flagged suspicious
    cluster_label  TEXT    DEFAULT 'Unclustered',        -- ML cluster category
    created_at     TEXT    DEFAULT (datetime('now'))
);

-- 2. JOBS TABLE (Internal Employer Postings)
CREATE TABLE jobs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    title       TEXT    NOT NULL,
    company     TEXT    NOT NULL,
    location    TEXT    DEFAULT '',
    type        TEXT    DEFAULT 'Full-time',             -- Full-time, Part-time, Contract, Internship
    salary      TEXT    DEFAULT '',                      -- e.g. "8-14 LPA"
    skills      TEXT    DEFAULT '',                      -- Required skill keywords
    description TEXT    DEFAULT '',
    status      TEXT    DEFAULT 'Active',                -- Active, Closed, Draft
    created_at  TEXT    DEFAULT (datetime('now'))
);

-- 3. EXTERNAL_JOBS TABLE (Live Aggregated Jobs from Adzuna API)
CREATE TABLE external_jobs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    external_id     TEXT    UNIQUE NOT NULL,             -- Provider prefixed ID (e.g. adzuna_123456)
    provider        TEXT    NOT NULL,                    -- 'Adzuna'
    title           TEXT    NOT NULL,
    company         TEXT    NOT NULL,
    company_id      TEXT    DEFAULT '',
    company_logo    TEXT    DEFAULT '',
    industry        TEXT    DEFAULT '',
    location        TEXT    DEFAULT '',
    country         TEXT    DEFAULT '',
    latitude        REAL    DEFAULT 0.0,
    longitude       REAL    DEFAULT 0.0,
    salary_min      REAL    DEFAULT 0.0,
    salary_max      REAL    DEFAULT 0.0,
    currency        TEXT    DEFAULT 'INR',
    employment_type TEXT    DEFAULT '',
    experience      TEXT    DEFAULT '',
    remote          INTEGER DEFAULT 0,                   -- 0 = onsite, 1 = remote
    description     TEXT    DEFAULT '',
    skills          TEXT    DEFAULT '',
    benefits        TEXT    DEFAULT '',
    education       TEXT    DEFAULT '',
    posted_date     TEXT    DEFAULT '',
    expires_date    TEXT    DEFAULT '',
    apply_url       TEXT    DEFAULT '',                  -- Direct redirect URL for application
    source_url      TEXT    DEFAULT '',
    language        TEXT    DEFAULT 'en',
    status          TEXT    DEFAULT 'Active',
    created_at      TEXT    DEFAULT (datetime('now'))
);

-- 4. RESUMES TABLE (Uploaded Resumes, Disk Pointers & Parsed Intelligence)
CREATE TABLE resumes (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id          INTEGER NOT NULL,
    original_name    TEXT    NOT NULL,                   -- Original client filename
    stored_filename  TEXT    UNIQUE NOT NULL,            -- UUID secure filename on persistent disk
    file_path        TEXT    NOT NULL,                   -- Absolute local storage path
    file_hash        TEXT    NOT NULL,                   -- SHA-256 binary hash for deduplication
    file_size_bytes  INTEGER NOT NULL,
    mime_type        TEXT    NOT NULL,                   -- application/pdf, application/vnd.openxmlformats...
    parsed_text      TEXT    DEFAULT '',                 -- Extracted text from PDF/DOCX
    word_count       INTEGER DEFAULT 0,
    ats_score        INTEGER DEFAULT 0,                  -- ATS score calculated at upload
    extracted_skills TEXT    DEFAULT '',                 -- Extracted comma-separated skills
    structured_json  TEXT    DEFAULT '',                 -- Full canonical JSON (contact, exp, edu, skills)
    status           TEXT    DEFAULT 'processed',        -- uploaded | processing | processed | failed
    version          INTEGER DEFAULT 1,
    uploaded_at      TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 5. APPLICATIONS TABLE (Core Candidate-to-Job Transaction Join)
CREATE TABLE applications (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,
    job_id      INTEGER NOT NULL,
    match_score INTEGER DEFAULT 0,                       -- AI match score computed at application time
    status      TEXT    DEFAULT 'Reviewing',             -- Reviewing | Shortlisted | Pending | Rejected
    applied_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY(job_id)  REFERENCES jobs(id)  ON DELETE CASCADE,
    UNIQUE(user_id, job_id)
);

-- 6. APPLICATION_STATUS TABLE (Status Transition History & Recruiter Notes)
CREATE TABLE application_status (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    application_id  INTEGER NOT NULL,
    status          TEXT    NOT NULL,                    -- Target status
    notes           TEXT    DEFAULT '',                  -- Recruiter decision comments
    updated_at      TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(application_id) REFERENCES applications(id) ON DELETE CASCADE
);

-- 7. SAVED_JOBS TABLE (Candidate Bookmarks)
CREATE TABLE saved_jobs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,
    job_id      INTEGER,                                 -- Nullable reference to internal jobs(id)
    external_id TEXT,                                    -- Nullable reference to external_jobs(external_id)
    saved_at    TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 8. RECOMMENDATION_HISTORY TABLE (AI Match Calculation Snapshots)
CREATE TABLE recommendation_history (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id         INTEGER NOT NULL,
    job_id          INTEGER,                             -- Nullable reference to internal jobs(id)
    external_id     TEXT,                                -- Nullable reference to external_jobs(external_id)
    match_score     INTEGER DEFAULT 0,                   -- Match score (0-100)
    matched_skills  TEXT    DEFAULT '',                  -- Overlapping skills
    missing_skills  TEXT    DEFAULT '',                  -- Skill gaps to acquire
    recommended_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 9. NOTIFICATIONS TABLE (User Alerts & System Updates)
CREATE TABLE notifications (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,
    title       TEXT    NOT NULL,
    message     TEXT    DEFAULT '',
    type        TEXT    DEFAULT 'info',                  -- info | success | error | warning | profile_view
    is_read     INTEGER DEFAULT 0,                       -- 0 = unread, 1 = read
    created_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 10. EMAIL_VERIFICATION_TOKENS TABLE (Account Activation)
CREATE TABLE email_verification_tokens (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,
    token_hash  TEXT    UNIQUE NOT NULL,                 -- SHA-256 hash of random 32-byte URL-safe token
    expires_at  TEXT    NOT NULL,                        -- 24 hours expiry timestamp
    is_used     INTEGER DEFAULT 0,                       -- 0 = unused, 1 = consumed
    created_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 11. PASSWORD_RESET_TOKENS TABLE (Password Recovery)
CREATE TABLE password_reset_tokens (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL,
    token_hash  TEXT    UNIQUE NOT NULL,                 -- SHA-256 hash of random 32-byte URL-safe token
    expires_at  TEXT    NOT NULL,                        -- 15 minutes expiry timestamp
    is_used     INTEGER DEFAULT 0,                       -- 0 = unused, 1 = consumed
    created_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

5. OBJECT-ORIENTED CLASS RELATIONSHIPS & MULTIPLICITY (UML LEVEL)
================================================================================

UML Strict Rules Applied:
- Composition (*--): The filled diamond is ALWAYS on the OWNER/PARENT side.
- Directed Association (-->): Used when one entity references another without owning its lifecycle.
- Cardinality Notation: 1 (Exactly one), 0..1 (Zero or one), 0..* (Zero or many).

1. User  "1" *-- "0..*" Resume
   - Type: Composition (Owner = User)
   - Reason: A user owns their uploaded resumes; deleting a user destroys all resumes.

2. User  "1" *-- "0..*" Application
   - Type: Composition (Owner = User)
   - Reason: A user submits applications; deleting the candidate profile removes applications.

3. Job   "1" <-- "0..*" Application
   - Type: Directed Association
   - Reason: A job receives applications from many candidates; the job does not own the user.

4. Application "1" *-- "0..*" ApplicationStatusHistory
   - Type: Composition (Owner = Application)
   - Reason: Status transition history records belong strictly to the application instance.

5. User  "1" *-- "0..*" SavedJob
   - Type: Composition (Owner = User)
   - Reason: Saved job bookmarks belong strictly to the saving user.

6. SavedJob "0..*" --> "0..1" Job
   - Type: Directed Association (Nullable Reference)
   - Reason: Bookmark optionally points to an internal job (job_id is nullable).

7. SavedJob "0..*" --> "0..1" ExternalJob
   - Type: Directed Association (Nullable Reference)
   - Reason: Bookmark optionally points to an external job (external_id is nullable).

8. User  "1" --> "0..*" RecommendationHistory
   - Type: Directed Association
   - Reason: System logs match calculations for a user; weak reference.

9. RecommendationHistory "0..*" --> "0..1" Job
   - Type: Directed Association (Nullable Reference)
   - Reason: Recommended target can be an internal job vacancy.

10. RecommendationHistory "0..*" --> "0..1" ExternalJob
    - Type: Directed Association (Nullable Reference)
    - Reason: Recommended target can be an external job vacancy.

11. User "1" *-- "0..*" Notification
    - Type: Composition (Owner = User)
    - Reason: Notifications belong strictly to the recipient user.

12. User "1" *-- "0..*" EmailVerificationToken
    - Type: Composition (Owner = User)
    - Reason: One-time verification tokens belong exclusively to the registered user.

13. User "1" *-- "0..*" PasswordResetToken
    - Type: Composition (Owner = User)
    - Reason: One-time reset tokens belong exclusively to the requesting user.

================================================================================
8. KEY ARCHITECTURAL GUIDELINES & RULES
================================================================================

1. ApplicationStatus vs. ApplicationStatusHistory:
   - ApplicationStatus is strictly an enumeration with 4 domain states:
     'Reviewing', 'Shortlisted', 'Pending', 'Rejected'.
   - ApplicationStatusHistory is the database audit class representing table
     'application_status' with columns id, application_id, status, notes, updated_at.
   - There is NO naming collision.

2. Candidate Profile on User:
   - In this implementation, candidate attributes (skills, ats_score, education,
     phone, location, linkedin, github, summary, is_outlier, cluster_label)
     reside directly on the User entity.
   - No separate CandidateProfile entity exists in this database version.

3. ExternalJob vs. Job:
   - ExternalJob is a separate table/class and does NOT inherit from Job.
   - Polymorphic handling is performed dynamically at the application layer.

4. Composition Diamonds:
   - Composition diamonds (*--) are placed strictly on the OWNER side:
     User owns Resume, Application, SavedJob, Notification, and Tokens.
     Application owns ApplicationStatusHistory.
   - SavedJob and RecommendationHistory maintain directed associations (-->)
     to Job and ExternalJob with optional multiplicity (0..1).
