1. EXECUTIVE OVERVIEW & TECHNOLOGY STACK
--------------------------------------------------------------------------------
TalentSync (HireAI) is an AI-powered resume screening, ATS optimization, and 
personalized live job recommendation platform.

Core Stack:
  • Backend: Python 3.14+, Flask (Application Factory & Blueprints)
  • Database: SQLite (WAL mode, parameterized queries, custom composite indexes)
  • NLP & ML Pipeline:
      - spaCy (custom SKILL NER model for skill extraction)
      - scikit-learn (TF-IDF vectorizer + Cosine Similarity for job matching)
      - scikit-learn (K-Means Clustering for candidate grouping)
      - scikit-learn (Isolation Forest for outlier & resume fraud detection)
  • External Integration:
      - Adzuna Live Jobs API (Multi-query personalization, single-flight coalescing,
        LRU cache with TTL & size cap, graceful threadpool timeouts)
  • Frontend:
      - Single Page Application (SPA) architecture
      - HTML5 Semantic Structure + Vanilla CSS (No heavy framework overhead)
      - Vanilla JavaScript Router, UI state management, and real-time DOM rendering
      - Chart.js for candidate analytics and dashboard metrics
  • Testing:
      - pytest test suite (419 unit, integration, and security regression tests)

4. DATA FLOW & LIFECYCLE
================================================================================

1. Candidate Resume Ingestion:
   Candidate uploads PDF/DOCX -> Magic bytes & extension validated -> SHA-256
   hash computed (detects duplicate files instantly).
   
2. NLP Parsing & Intelligence Extraction:
   spaCy SKILL NER extracts domain technical skills, soft skills, and frameworks.
   Education, contact information, and experience are parsed and serialized to
   canonical structured_json in the resumes table.

3. ATS Score Calculation:
   compute_ats_score() scores the resume from 0 to 100 based on weighted
   categories: Skills match (40%), Contact info (10%), Education (15%),
   Experience completeness (20%), and Content formatting (15%). Missing
   high-value market keywords are identified.

4. Multi-Query Live Job Matching (/api/match_jobs):
   Candidate's skills and location trigger up to 3 concurrent live queries to
   Adzuna via ThreadPoolExecutor. If one query times out, results from the
   others are preserved.
   Results are merged, deduplicated, and passed to JobMatcher.rank_jobs()
   which calculates TF-IDF cosine similarity between candidate skills and job
   descriptions.

5. Unified Job Search & Filtering (/api/jobs/search):
   Candidate searches with keywords, location, salary min, work mode, and
   experience brackets. Searches both local partner jobs and live Adzuna jobs.
   Jobs with unspecified experience or salary are retained so candidates are
   not excluded from open opportunities.

6. Application Submission (/api/apply):
   - Internal Jobs: Recorded directly in the applications table.
   - External Jobs (Adzuna): Strictly validated for safe HTTPS redirect URL,
     returning redirect_url to open external partner site in a new tab
     (noopener,noreferrer).

5. DATABASE SCHEMA SUMMARY (talentsync.db)
================================================================================

Table: users
  • id (INTEGER PRIMARY KEY)
  • name (TEXT)
  • email (TEXT UNIQUE)
  • password (TEXT - werkzeug scrypt hash)
  • role (TEXT - 'candidate' | 'hr' | 'admin')
  • skills (TEXT - comma separated)
  • ats_score (REAL)
  • location (TEXT)
  • phone, linkedin, github, summary, education (TEXT)
  • is_outlier (INTEGER - 0 or 1)
  • cluster_label (TEXT)
  • is_verified (INTEGER - 0 or 1)
  • created_at (TIMESTAMP)

Table: resumes
  • id (INTEGER PRIMARY KEY)
  • user_id (INTEGER REFERENCES users(id))
  • original_name, stored_filename, file_path (TEXT)
  • file_hash (TEXT - SHA-256 for deduplication)
  • file_size_bytes, mime_type, parsed_text, word_count (METADATA)
  • ats_score (REAL)
  • extracted_skills (TEXT)
  • structured_json (TEXT - canonical resume intelligence)
  • status, version, uploaded_at (METADATA)

Table: jobs
  • id (INTEGER PRIMARY KEY)
  • title, company, location, type (TEXT)
  • salary, salary_min, salary_max (INTEGER / TEXT)
  • work_mode (TEXT - 'remote' | 'onsite' | 'hybrid')
  • skills, description, status ('Active' | 'Closed')
  • created_at, created_by (METADATA)

Table: applications
  • id (INTEGER PRIMARY KEY)
  • user_id (INTEGER REFERENCES users(id))
  • job_id (INTEGER REFERENCES jobs(id))
  • resume_id (INTEGER REFERENCES resumes(id))
  • match_score, ats_score (REAL)
  • status (TEXT - 'Pending' | 'Reviewing' | 'Shortlisted' | 'Rejected')
  • applied_at (TIMESTAMP)

6. SECURITY & ROLES MATRIX (RBAC)
================================================================================

Role: candidate
  • Can upload resumes, view own ATS analysis, receive personalized matches,
    apply to jobs, and view personal application history.
  • Ownership Guard: Candidate A cannot download Candidate B's resume (HTTP 403).

Role: hr / recruiter
  • Can post/edit/close internal job listings, view applicants for their jobs,
    access candidate ATS scores, download applicant resumes, and update
    application statuses ('Shortlisted', 'Rejected', etc.).

Role: admin (Platform Administrator)
  • Access to system-wide KPI analytics (live user counts, application volumes,
    ATS distribution).
  • User management: can activate/deactivate accounts and change user roles.
  • Safeguards: Cannot deactivate own account; cannot demote the last remaining admin.
