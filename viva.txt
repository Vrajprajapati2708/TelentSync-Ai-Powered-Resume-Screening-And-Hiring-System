1. WHAT IS IT?
- Python 3.11: Python is a high-level, interpreted, dynamically-typed, general-purpose programming language. Python 3.11 is the major version release that introduced significant CPython interpreter optimizations (Faster CPython project), offering 10% to 60% speedups over Python 3.10.
- Virtual Environment (venv): An isolated, self-contained directory tree that contains a specific Python binary alongside its own dedicated set of installed packages, preventing global dependency pollution.
- pip: Python’s standard package manager used to install, update, and manage third-party libraries from the Python Package Index (PyPI).
- requirements.txt: A plain text manifest file that lists all exact third-party package dependencies and pinned versions required to replicate the project runtime.

2. WHY WAS IT CREATED?
- Python: Created by Guido van Rossum in 1991 to emphasize code readability, developer productivity, and clean syntax, replacing cumbersome languages for rapid script execution.
- Virtual Environments: Solved "Dependency Hell" where Project A needed library X v1.0 and Project B needed library X v2.0 on the same OS.
- pip & requirements.txt: Standardized open-source code distribution so projects could be built anywhere reproducibly with a single installation command.

3. WHY DO COMPANIES USE IT?
- Python dominates AI/ML, Data Engineering, and Web Development because of rich open-source libraries (NumPy, PyTorch, spaCy, Flask), rapid prototyping capabilities, and massive enterprise support.

4. WHY DID I CHOOSE IT IN HIREAI?

import fitz  # PyMuPDF

def extract_text_from_pdf(pdf_path: str) -> str:
    text = ""
    with fitz.open(pdf_path) as doc:
        for page in doc:
            text += page.get_text("text") + "\n"
    return text.strip()
```

import spacy
from spacy.matcher import Matcher

nlp = spacy.load("en_core_web_sm")

def extract_skills(text: str) -> list[str]:
    doc = nlp(text)
    extracted = set()
    
    # 1. Custom NER entities
    for ent in doc.ents:
        if ent.label_ in ["SKILL", "ORG", "PRODUCT"]:
            extracted.add(ent.text.strip())
            
    # 2. Rule-based Matcher for multi-word skills
    matcher = Matcher(nlp.vocab)
    pattern = [{"LOWER": "machine"}, {"LOWER": "learning"}]
    matcher.add("ML_PATTERN", [pattern])
    matches = matcher(doc)
    for match_id, start, end in matches:
        extracted.add(doc[start:end].text)
        
    return list(extracted)
```

Answer: Stemming uses crude heuristic rules to chop off word ends (e.g., "studies" -> "studi"), which often creates non-dictionary words. Lemmatization uses vocabulary and morphological analysis to return valid base dictionary words (e.g., "studies" -> "study").

MODULE 7: MACHINE LEARNING & CANDIDATE RANKING ENGINE
[Technologies Covered: 31. Scikit-learn, 32. ML Basics, 33. TF-IDF, 34. Bag of Words, 35. Cosine Similarity, 36. Candidate Ranking Algorithm]
==================================================================================================

1. WHAT IS IT?
- TF-IDF (Term Frequency-Inverse Document Frequency): A numerical statistic reflecting how important a word is to a document in a collection or corpus.
  TF(t, d) = (Count of term t in doc d) / (Total words in doc d)
  IDF(t, D) = log( Total documents N / (1 + Count of documents containing term t) )
  TF-IDF = TF * IDF
- Cosine Similarity: A metric measuring cosine of the angle between two multi-dimensional vectors in vector space:
  Cosine Similarity(A, B) = (A · B) / (||A|| * ||B||)

2. VECTOR SPACE GEOMETRY & MATHEMATICAL MATCHING

ASCII Cosine Similarity Diagram:

                Vector A (Resume)
                   ^
                  / 
                 /   θ (Angle between vectors)
                /--------> Vector B (Job Description)
               (0,0)

  When θ = 0°, Cosine(0°) = 1.0 (100% Perfect Match)
  When θ = 90°, Cosine(90°) = 0.0 (0% Match / Orthogonal)

3. CODE WALKTHROUGH (`app/ml/recommendation/recommend_jobs.py`)

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

def recommend_jobs(candidate_skills: list[str], jobs: list[dict], top_n: int = 10) -> list[dict]:
    candidate_str = " ".join(candidate_skills)
    job_descriptions = [j.get('description', '') for j in jobs]
    
    corpus = [candidate_str] + job_descriptions
    
    vectorizer = TfidfVectorizer(stop_words='english')
    tfidf_matrix = vectorizer.fit_transform(corpus)
    
    # Candidate vector is at index 0, job vectors are from index 1 onwards
    candidate_vec = tfidf_matrix[0:1]
    job_vecs = tfidf_matrix[1:]
    
    similarities = cosine_similarity(candidate_vec, job_vecs).flatten()
    
    results = []
    for idx, job in enumerate(jobs):
        sim_score = float(similarities[idx])
        results.append({
            'title': job['title'],
            'match_percentage': round(sim_score * 100, 2),
            'raw_score': sim_score
        })
        
    results.sort(key=lambda x: x['match_percentage'], reverse=True)
    return results[:top_n]
```

Line-by-Line Breakdown:
- `TfidfVectorizer(...)`: Instantiates vectorizer object with English stop-words filtering.
- `fit_transform(corpus)`: Learns vocabulary dictionary and builds N x M sparse matrix of TF-IDF feature weights.
- `cosine_similarity(...)`: Computes dot product of normalized sparse vectors to derive angular closeness.
- `results.sort(...)`: Sorts ranked job list in descending order of match percentage.

4. COMPLEXITY ANALYSIS
- Vectorization Time Complexity: O(N * L) where N is number of documents and L is document length.
- Cosine Similarity Complexity: O(D * V) where D is job count and V is vocabulary vector dimension. Runs in < 25ms.

5. VIVA & COUNTER QUESTIONS

Viva Question: Why use Cosine Similarity instead of Euclidean Distance?
Answer: Euclidean distance measures raw magnitude distance between vector endpoints, penalizing resumes simply because they are shorter or longer in word count. Cosine similarity measures angular orientation, evaluating term ratio balance regardless of document length.

1. WHAT IS IT?
- Cryptographic Hashing: One-way mathematical transformation of plaintext data into a fixed-length string that cannot be reversed.
- Salting: Appending a cryptographically random unique string to a password prior to hashing to render Rainbow Table attacks ineffective.
- Bcrypt: An adaptive cryptographic hash function based on the Blowfish cipher incorporating configurable work factors (cost factors) to slow down brute-force hardware attacks.
- Rate Limiting (Flask-Limiter): Throttling incoming client request rates per unit time based on client IP or session tokens to prevent Denial of Service (DoS) and brute-force attacks.

2. CRYPTOGRAPHIC PIPELINE

ASCII Hashing & Salting Flow:
Password ("Secret123") + Random Salt ("a8f9z3") ──► Bcrypt Key Derivation (2^12 Iterations) ──► Hash Hash ($2b$12$a8f9z3...)

# Password Verification

4. VIVA & COUNTER QUESTIONS

Viva Question: Why is MD5 or SHA-256 unsuitable for password storage?
Answer: MD5 and SHA-256 are fast hash functions designed for speed. Modern GPUs can calculate billions of SHA-256 hashes per second, allowing rapid brute-force recovery of passwords. Bcrypt is deliberately slow and includes an adjustable cost factor to neutralize hardware brute-forcing.
