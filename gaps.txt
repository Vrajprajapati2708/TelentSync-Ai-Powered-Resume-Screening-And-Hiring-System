2. CRITICAL P0 GAPS (FUNCTIONAL BROKENNESS, BUGS & DISCONNECTS)
================================================================================

[GAP-01] Resume Intelligence (RI) Data Disconnected from Frontend UI
- Affected Files:
    app/controllers/resume_controller.py (Line 236)
    app/static/js/app.js (Line 1290)
    app/templates/index.html (Line 752 - cand-analysis)
- Problem:
    The backend builds rich, highly detailed Resume Intelligence data (work experience
    timeline, companies, job titles, duration, education records with degrees/GPA,
    quality score breakdown, action verb density, and section completeness) and saves
    it to resumes.structured_json. However:
    1. resume_controller.py:236 only returns legacy flat fields (skills, ats_score).
       The canonical intelligence object ('intel') is omitted from the API response.
    2. index.html contains an unpopulated 'Projects Extracted' placeholder and a
       basic contact table. There is no UI rendering the candidate's parsed work
       experience, education history, or ATS quality breakdown.
- Impact:
    The most advanced AI feature built on Aug 11 is completely invisible to users.

[GAP-02] Frontend Resume Upload Error Handling Crash
- Affected File:
    app/static/js/app.js (Line 1293)
- Problem:
    In app.js:
        if (data.error) { ... }
    However, resume_controller.py returns errors formatted as:
        {'success': False, 'message': 'Validation error message'}
    Because data.error is undefined, the failure branch is skipped. The code executes
    the success branch, changes the progress bar to green, and attempts to access
    data.data.ats_score, resulting in an unhandled JavaScript error:
    "TypeError: Cannot read properties of undefined (reading 'ats_score')".
- Impact:
    Whenever an upload fails (e.g. file size > 5MB, invalid extension, corrupted PDF),
    the UI hangs in a broken state instead of displaying the error message toast.

[GAP-03] Uploaded Resumes Disappear on Refresh (Missing API Sync)
- Affected Files:
    app/routes/resume_routes.py (Line 68 - /api/resume/my_resumes)
    app/static/js/app.js (Line 1963 - renderUploadHistory)
- Problem:
    The backend provides a secure endpoint GET /api/resume/my_resumes that returns all
    resumes uploaded by the logged-in candidate.
    However, app.js NEVER calls this endpoint. Instead, renderUploadHistory() creates
    a single temporary card from user.ats_score. When the page is refreshed or
    the candidate logs in from a different browser, their resume list is lost.
- Impact:
    Candidates cannot view their past uploaded resumes, versions, or upload dates.

[GAP-04] No Resume Download or Preview Buttons in UI
- Affected Files:
    app/routes/resume_routes.py (Line 30 - /api/resume/download/<id>)
    app/static/js/app.js (Line 735, Line 997, Line 1963)
    app/templates/index.html
- Problem:
    The backend has a secured download endpoint (/api/resume/download/<id>) with
    ownership authorization checks (candidates download their own, HR downloads all).
    However, neither the candidate dashboard nor the recruiter applicant table
    (renderCandidatesTable) or candidate detail modal (viewCandidate) provides a
    "Download Resume" or "Preview" link/button.
- Impact:
    Recruiters cannot download or review the actual PDF/DOCX resume file submitted
    by the candidate.

[GAP-05] Client vs Server Password Length Mismatch
- Affected Files:
    app/static/js/app.js (Line 330)
    app/utils/validators.py (Line 50)
- Problem:
    In app.js:
        if (pass.length < 6) { Toast.show('Password must be at least 6 characters'); return; }
    In validators.py:
        MIN_PASSWORD_LENGTH = 10
    If a user enters a 7-9 character password, the client-side validation passes, but
    the server rejects the registration with HTTP 400.
- Impact:
    Poor user experience and confusing validation error upon registration.

[GAP-06] Database Path is Relative ('talentsync.db') Causing Database Split
- Affected Files:
    app/config/settings.py (Line 43)
    app/database/connection.py (Line 18)
- Problem:
    ActiveConfig.DB_FILE = "talentsync.db" is a relative path.
    Depending on the current working directory from which Python is launched:
    - Running from project root uses V:\HireAI_Website-main (2)\talentsync.db (151 KB)
    - Running from AI-Resume-Screening-System uses AI-Resume-Screening-System\talentsync.db (1.2 MB)
    - Running from tests/ creates another temporary talentsync.db in tests/.
- Impact:
    Data divergence, missing tables, or apparent loss of candidate accounts depending
    on where the CLI command was started. Must be an absolute path based on PROJECT_ROOT.

[GAP-07] External Jobs Application Failure (HTTP 404)
- Affected Files:
    app/routes/resume_routes.py (Line 126 - apply_job)
    app/services/adzuna_service.py
    app/routes/jobs_routes.py
- Problem:
    External/Adzuna jobs return string IDs (e.g. adzuna_49201948).
    When a candidate clicks "Apply Now", apply_job() queries:
        SELECT id FROM jobs WHERE id=?
    Because the external job is not in the internal jobs table, it fails with 404 "Job not found".
- Impact:
    Candidates cannot apply to live external job postings aggregated from Adzuna.

- Affected Files:
    app/routes/admin_routes.py (Line 140 - get_candidates)
- Problem:
    admin_routes.py queries:
        SELECT ... FROM applications a JOIN users u ON a.user_id = u.id ...
    If a candidate signs up, uploads a resume, and receives an ATS score, but has
    not yet submitted an application for a specific vacancy, HR never sees them
    in the Candidates list or Talent Pool.
- Solution Needed:
    Provide an all-candidates talent pool endpoint (or LEFT JOIN applications) so
    HR can browse all registered candidates, filter by skill, and invite them to apply.

[GAP-11] Allowed Extensions Mismatch in settings.py
- Affected Files:
    app/config/settings.py (Line 49)
    app/utils/validators.py (Line 29)
- Problem:
    settings.py still specifies:
        ALLOWED_EXTENSIONS = {"pdf", "doc", "docx"}
    However, docx_parser.py throws an unhandled exception on legacy binary .doc files,
    which the Phase 1 audit marked as P0. validators.py was updated, but settings.py
    and the index.html file input (<input accept=".pdf,.doc,.docx">) still advertise .doc.
- Solution Needed:
    Remove 'doc' from settings.py and HTML accept attributes, restricting uploads to
    {'pdf', 'docx'}.

[GAP-12] Email Subsystem is Mocked (Tokens Returned in JSON Response)
- Affected Files:
    app/routes/auth_routes.py (Line 103, Line 118)
    app/controllers/auth_controller.py
- Problem:
    Currently, generate_password_reset_token() and resend_verification() return
    the raw security tokens in the JSON HTTP response (dev_verification_token, dev_reset_token)
    because no SMTP or email API (e.g. SendGrid, Mailgun, SMTP via Python smtplib) is connected.
- Solution Needed:
    Create an email service module (app/services/email_service.py) with SMTP configuration
    in settings.py and .env to send genuine HTML verification and reset emails.

       "Model 'en_pipeline' (0.0.0) was trained with spaCy v3.7.2 and may not be 100% compatible
       with the current version (3.8.13)."

       "Setting the shape on a NumPy array has been deprecated in NumPy 2.5."
- Solution Needed:
    Run python -m app.ml.training.train_all inside the current environment to regenerate
    both models natively on scikit-learn 1.9.0 and spaCy 3.8.13.

[GAP-14] Scanned / Image-Based PDF Parsing (No OCR Fallback)
- Affected Files:
    app/ml/parsers/pdf_parser.py
- Problem:
    If a resume PDF consists of scanned images instead of selectable text, PyPDF2
    extracts 0 characters, causing the parser to fail and return an empty resume error.
- Solution Needed:
    Integrate pytesseract / pdf2image fallback when extracted text character count
    is below 50 characters.

[GAP-15] Directory Structure Duplication (Outer vs Inner Folder)
- Affected Paths:
    V:\HireAI_Website-main (2)\
    V:\HireAI_Website-main (2)\AI-Resume-Screening-System\
- Problem:
    The outer repository folder contains duplicate datasets, trained_models,
    talentsync.db, and markdown files, while the inner AI-Resume-Screening-System
    contains the actual application, .venv, and app/ code.
    Some scripts (e.g. extract_skills.py:23) use .parents[4] to reach the outer folder,
    while others use .parents[3] to reach the inner folder.
- Solution Needed:
    Consolidate all paths to a single canonical root directory to avoid path confusion.

[GAP-16] In-Memory Rate Limiting Backend
- Affected Files:
    app/__init__.py (Line 20)
- Problem:
    Limiter storage uses storage_uri="memory://". If deployed behind multiple Gunicorn
    workers or multiple server instances, the rate limit is not synchronized across workers.
- Solution Needed:
    Support REDIS_URL in settings.py so production can seamlessly use Redis.

5. LOW-PRIORITY P3 GAPS (PRODUCTION DEPLOYMENT & ENTERPRISE SCALABILITY)
================================================================================

[GAP-17] Missing Production WSGI Configuration & Docker Setup
- Affected Files:
    run.py
    Dockerfile (Missing)
    docker-compose.yml (Missing)
- Problem:
    run.py uses Flask's built-in single-threaded development server (app.run(debug=True)).
    There is no Gunicorn configuration, Procfile, Dockerfile, or systemd service file.
- Solution Needed:
    Add a production entrypoint (e.g. wsgi.py), Dockerfile, and docker-compose.yml.

[GAP-18] SQLite Concurrency Limitations for Enterprise Workloads
- Affected Files:
    app/database/connection.py
    app/database/schema.sql
- Problem:
    SQLite locks the entire database file on write operations. Under concurrent candidate
    uploads or bulk recruiter actions, SQLite can throw "database is locked" errors.
- Solution Needed:
    Abstract database connection so DATABASE_URL can point to PostgreSQL / MySQL
    via SQLAlchemy or psycopg2.
