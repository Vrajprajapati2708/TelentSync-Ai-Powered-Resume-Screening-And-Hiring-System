1. EXECUTIVE SUMMARY & VERIFIED SYSTEM BASELINE
====================================================================================================
TalentSync (HireAI) is an enterprise-grade AI resume screening, job recommendation, and talent
acquisition platform. The system operates on a dual-engine recommendation pipeline combining local
SQL internal jobs with real-time live Adzuna external job market postings, backed by spaCy Named
Entity Recognition (NER), scikit-learn TF-IDF vectorization, cosine similarity ranking, and
canonical resume intelligence parsing.

Backend:

  PlatformAdminState)

Machine Learning & Parsing:
- Resume Parsers: python-docx (DOCX), PyPDF2 & pdfplumber (PDF)
- NLP & Skill Extraction: spaCy custom NER model ('trained_models/spacy_skill_ner') + curated 2,400+
  canonical skills taxonomy
- Job Matching: scikit-learn TF-IDF Vectorizer (4,206 vocabulary terms) + Cosine Similarity
- Clustering: MiniBatchKMeans / KMeans (k=5 candidate clustering)
- Outlier Detection: IsolationForest (anomaly detection for candidate quality/ATS divergence)

External Integrations:
- Adzuna Jobs API: Multi-query parallel fetching, role inference, location filtering, client-side
  caching (5 min TTL), contract hardening, and secure redirection

3. PRODUCTION DATABASE & FILE SYSTEM INVENTORY
====================================================================================================
Database Tables in 'talentsync.db':
1. users:
   - Primary user table storing candidates, HR recruiters, and administrators.
   - Fields: id, name, email, password, role ('candidate'|'hr'|'admin'), location, education,
     skills, ats_score, phone, linkedin, github, summary, is_verified, created_at.
2. resumes:
   - Parsed resume metadata, ATS calculations, extracted skills, and full structured JSON.
   - Fields: id, user_id, original_name, stored_filename, file_path, file_hash, file_size_bytes,
     mime_type, parsed_text, word_count, ats_score, extracted_skills, structured_json,
     status, version, uploaded_at.
3. jobs:
   - Internal employer job postings.
   - Fields: id, title, company, description, location, required_skills, min_experience_years,
     salary_range, job_type, created_at.
4. applications:
   - Candidate internal job applications.
   - Fields: id, user_id, job_id, match_score, status ('Pending'|'Reviewing'|'Shortlisted'|'Rejected'),
     applied_at.
5. notifications:
   - In-app notification and audit log events.
   - Fields: id, user_id, title, message, type ('info'|'success'|'warning'|'danger'), is_read, created_at.
6. login_attempts:
   - Security audit log for brute-force protection and lockout management.
   - Fields: id, email, ip_address, success, attempt_time.
7. tokens:
   - Email verification and password reset tokens.
   - Fields: id, user_id, token_hash, token_type ('verify'|'reset'), expires_at, used_at.

File Storage:
- uploads/resumes/: Stores physical resume files on disk (.pdf, .docx).
- uploads/temp/: Temporary buffer directory for processing uploads.

8. SECURITY, RBAC, & DATA INTEGRITY CONTROLS
====================================================================================================
1. IDOR & Ownership Verification:
   - In resume deletion and downloads, the user ID in the session is strictly compared to the resume's
     recorded owner ID (`resume['user_id'] == current_user_id`).
   - Cross-candidate tampering returns HTTP 403 Forbidden.
2. Path Traversal & Disk Jail:
   - File operations canonicalize paths via `os.path.realpath`.
   - Any path escaping the designated upload directory or containing `..`, `/`, `\` is rejected with
     HTTP 400 Bad Request.
3. CSV Formula Injection Defense (CWE-1236):
   - Cells beginning with spreadsheet formula triggers (`=, +, -, @, \t, \r`) are automatically escaped
     with a leading `'` before CSV emission.
4. Production Data Immutability:
   - Unit and integration tests run under `TestingConfig`, directing DB writes to an isolated temporary
     database (`talentsync_test.db`) and isolated upload folder in the OS temp directory.
   - Production business data is never modified by automated test suites.
5. Referential & History Integrity:
   - Deleting a resume updates profile ATS metrics from remaining resumes, but NEVER deletes past
