## 5. Test Mutation Analysis

Code inspection of the test suites (`tests/test_auth_p0.py`, `test_phase1_stability_regression.py`, `test_phase2_resume_intelligence_regression.py`, `test_phase3_jobs_talent_pool_regression.py`, `test_phase4_email_ml_ocr_regression.py`, and `test_ri_integration_05_persistence.py`) revealed the structural root cause:

1. **Direct Coupling to Active Database**:
   - Tests instantiate the application via `create_app()` without specifying an isolated test database.
   - In `app/config/settings.py`, `ActiveConfig.DB_FILE` points to `AI-Resume-Screening-System/talentsync.db`.
   - Even `TestingConfig` inherits `DB_FILE` and `UPLOAD_FOLDER` from `Config`, pointing to the active runtime paths.
2. **Absence of `tearDown` Data Deletion**:
   - In `tests/test_auth_p0.py`:
     ```python
     def get_unique_email(self, prefix="user"):
         return f"{prefix}_{int(time.time() * 1000)}@example.com"
     ```
   - Tests were deliberately architected from Phase 0 with timestamped unique emails specifically to avoid collisions with prior test rows in `talentsync.db`.
   - Neither `setUp` nor `tearDown` cleans up test rows or disk uploads.
3. **Upload Persistence in Integration Tests**:
   - When tests invoke `process_resume_upload()` or POST to `/api/resume/upload`, the application correctly executes its business logic: saves the file to `uploads/resumes/` and inserts into `resumes`.

## 7. Root Cause

1. **Database Hash Discrepancy**:
   - **Classification: B — TEST-INDUCED MUTATION**.
   - The test suite execution (Task 1387) ran 289 tests against `talentsync.db`, appending test users, tokens, and resume records.
   - This modified the SQLite file pages and updated its SHA-256 hash.
2. **Resume File Count Discrepancy**:
   - **Classification: B — TEST FIXTURE CREATION**.
   - Exactly 18 upload tests executed during Task 1387, uploading 18 test resumes (`.docx` / `.pdf`) into `uploads/resumes/`.
   - File count moved from 418 (post-Phase 5 implementation) to 436 (post-Golden Checkpoint test suite execution).

## 11. Required Remediation (For Authorized Phase)

To permanently resolve this in a future authorized step:
1. **Isolate Test Database in `TestingConfig`**:
   Set `TestingConfig.DB_FILE = os.path.join(tempfile.gettempdir(), 'talentsync_test.db')` or use an ephemeral in-memory SQLite database (`sqlite:///:memory:`).
2. **Isolate Test Upload Storage**:
   Set `TestingConfig.UPLOAD_FOLDER = os.path.join(tempfile.gettempdir(), 'talentsync_test_uploads')`.
3. **Enforce `TestingConfig` in All Test Suites**:
   Ensure every test suite in `tests/` explicitly passes `TestingConfig` to `create_app()`.
4. **Restore Active Database & Storage**:
   Restore `talentsync.db` from `talentsync_backup_phase5.db` and prune the 18 test fixtures from `uploads/resumes/`.
